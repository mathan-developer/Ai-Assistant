# RAG backend (py_scripts)

Semantic search + retrieval-augmented generation over `dataset/questions.json`.
Embeddings are produced with `all-MiniLM-L6-v2`; answers are generated by a
local [Ollama](https://ollama.com) model (`mistral`).

## Layout

```
py_scripts/
  retrieval.py              # shared: model, vectorized search, ask_llm()
  requirements.txt          # pinned dependencies
  run.sh                    # convenience runner (always runs from repo root)
  scripts/
    generate_embeddings.py  # builds dataset/embeddings.json
    vector_search.py        # interactive semantic search (no LLM)
  backend/
    rag_pipeline.py         # interactive RAG (search + LLM) in the terminal
    api_server.py           # FastAPI /ask endpoint
```

The dataset lives at the **repo root** in `dataset/`. All scripts resolve that
path relative to the source files, so they work regardless of your current
directory.

## Setup

Requires Python 3.11 (PyTorch has no wheels for 3.14 yet).

```bash
./py_scripts/run.sh install
```

This creates `py_scripts/.venv` and installs `requirements.txt`.

## Usage

```bash
./py_scripts/run.sh embeddings   # (re)generate dataset/embeddings.json
./py_scripts/run.sh search       # interactive vector search
./py_scripts/run.sh rag          # interactive RAG (needs Ollama running)
./py_scripts/run.sh api          # serve FastAPI on http://0.0.0.0:8000
```

### API

With the server running:

```bash
curl -X POST http://localhost:8000/ask \
  -H "Content-Type: application/json" \
  -d '{"question": "How does binary search work?"}'
```

Response:

```json
{ "answer": "...", "context": "..." }
```

Interactive docs are at `http://localhost:8000/docs`.

## Notes

- The RAG/API paths call Ollama at `http://localhost:11434`. Start it with
  `ollama run mistral` (or `ollama serve`) first; otherwise the API returns a
  `502` with an error detail instead of crashing.
- Re-run `embeddings` whenever `dataset/questions.json` changes.
